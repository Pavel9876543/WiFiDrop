# WiFiDrop


## Подключение через роутер

WiFiDrop работает на компьютере. Компьютер (Wi-Fi или Ethernet) и телефон должны быть подключены к одному роутеру. Установка приложения на сам роутер не требуется.

1. Запустите привычный `WiFiDrop.vbs` / `run_gui.bat` и выберите **«Через роутер»**.
2. Откройте **«Настройки WiFiDrop»**, выберите IP компьютера на адаптере Wi-Fi/Ethernet, при необходимости задайте локальное имя и нажмите **«Сохранить настройки»**. При нескольких адаптерах/VPN проверьте адрес; это IP компьютера, а не шлюз роутера.
3. Нажмите **«Запустить WiFiDrop»**. В окне появятся HTTP-адрес с портом и QR-код. QR также сохраняется как **`wifidrop_qr.png` в корне проекта**; новый запуск заменяет изображение.
4. Подключите телефон к тому же роутеру и откройте полный адрес, например `http://192.168.1.20:8000/`, или отсканируйте QR камерой и перейдите по ссылке.

Режим сохраняется в `.env`. Для консольного запуска через роутер используйте `run_router.bat` или `CONNECTION_MODE=router python start.py` (Linux/macOS). Обычный `python start.py` использует сохранённый режим; `run_hotspot.bat` явно включает хот-спот.

В режиме роутера **не запускаются создание Wi-Fi, DHCP, DNS-перехват и Captive Portal**, независимо от старых флагов. Подключение к Wi-Fi и открытие сайта выполняются вручную. Существующий режим **«Мобильный хот-спот»** сохраняет прежний запуск.

### Локальное доменное имя

- **mDNS (по умолчанию)**: введите `otrozhka` — адрес станет `http://otrozhka.local:8000/`. Можно ввести `отрожка`; кириллица сохраняется в настройках, а URL QR использует совместимое IDNA-представление (`http://xn--80almoaln.local:8000/`). Программа объявляет только выбранное имя на выбранном интерфейсе; DNS роутера не меняется. Клиент должен поддерживать mDNS, а сеть — разрешать multicast (UDP 5353). При конфликте имени или ошибке mDNS программа сообщает причину и создаёт QR по IP.
- **DNS роутера**: выберите этот способ и заранее создайте на роутере DNS-запись, например `otrozhka` → `192.168.1.20`, и закрепите IP компьютера через DHCP reservation. Тогда можно открыть `http://otrozhka:8000/`. Поддержка таких записей зависит от модели роутера. Программа проверяет, что имя разрешается на выбранный IP; если проверка не проходит, QR содержит IP. На телефоне должен использоваться DNS этого роутера; защищённый/внешний DNS может обходить локальную запись. Суффикс `.local` используйте только с mDNS.

При доступном имени QR содержит доменный HTTP URL с портом; IP-адрес остаётся в окне и консоли для запасного подключения. Имя и способ его разрешения можно менять в настройках после остановки сервера.

Для адреса без явного `:8000` установите **порт сайта 80**, если он свободен, и открывайте `http://otrozhka.local/` или имя из DNS роутера. DNS/mDNS сами по себе не передают браузеру HTTP-порт. Ввод одного слова без `http://` может отправить поисковый запрос: это поведение и подсказки задаёт браузер. Приложение не управляет подсказками и не открывает сайт автоматически при подключении к роутеру. Надёжный способ — полный HTTP URL или QR.

Если сайт недоступен по IP, проверьте Windows Firewall (разрешите Python входящие подключения в **частной сети** на порт сайта), адрес и порт, а также изоляцию клиентов/гостевой Wi-Fi на роутере. Для mDNS дополнительно нужен UDP 5353. Режим роутера не меняет системные сетевые настройки и не запрашивает настройку DHCP/DNS хот-спота.


WiFiDrop — локальное веб-приложение для передачи файлов с телефона, планшета или
другого компьютера на Windows-ПК через обычный браузер. Все устройства должны быть
подключены к одной локальной Wi-Fi сети. Облачные сервисы, аккаунт, база данных и
интернет для передачи файлов не нужны.

После выбора файлов WiFiDrop потоково сохраняет их в папку `Files`, автоматически
определяет категорию и создаёт подпапку с текущей датой. Файлы с одинаковыми именами
не перезаписываются.

## Возможности

- одиночная и множественная загрузка;
- выбор через системный диалог и Drag & Drop;
- поддержка файлов любых типов и файлов нулевого размера;
- индивидуальный и общий прогресс;
- отмена текущей загрузки, отдельного файла или всей оставшейся очереди;
- отображение размера, скорости и результата каждого файла;
- повторная отправка только неудачных файлов;
- защита от перегрузки при одновременной отправке с нескольких устройств;
- понятное сообщение «Сервер занят» без запуска всей оставшейся очереди;
- автоматическая классификация по расширению и MIME-типу;
- автоматические папки категорий и дат;
- уникальные имена при совпадениях: `photo.jpg`, `photo (1).jpg` и далее;
- адаптивный интерфейс для телефона, планшета, ноутбука и ПК;
- светлая и тёмная темы;
- потоковая запись без загрузки всего файла в оперативную память приложения;
- атомарное завершение записи и удаление незавершённых `.part`-файлов при ошибке;
- понятные JSON-ошибки без traceback для пользователя;
- журнал запусков, остановок, загрузок, предупреждений, ошибок и IP клиентов;
- ежедневная ротация и автоматическое удаление устаревших логов;
- настройка через `.env` без изменения Python-кода;
- запуск напрямую на Windows или в Docker одной командой.

## Требования

- для обычного запуска: Windows 10/11 и Python 3.12+ с Python Launcher (`py`);
- для контейнерного запуска: Docker Desktop / Docker Engine или Podman с Compose;
- устройства находятся в одной Wi-Fi сети;
- интернет нужен только при первой установке зависимостей или сборке образа.

Для обычного запуска при установке Python с
[python.org](https://www.python.org/downloads/windows/)
рекомендуется включить опции **Add Python to PATH** и **Install launcher for all users**.

## Быстрый запуск на Windows

Откройте Command Prompt (cmd) в папке проекта и выполните:

```bat
run.bat
```

Также можно просто дважды щёлкнуть `run.bat` в Проводнике.

При первом запуске скрипт:

1. проверит версию Python;
2. создаст изолированное окружение `.venv`;
3. установит зависимости из `requirements.txt`;
4. запустит WiFiDrop на всех локальных сетевых интерфейсах.

При последующих запусках интернет не требуется. Сервер печатает адрес для этого ПК и
обнаруженные адреса локальной сети. Для остановки нажмите `Ctrl+C` или закройте окно.

> При первом запуске Windows Firewall может запросить разрешение. Разрешите Python
> доступ для **частных сетей**. Доступ для публичных сетей WiFiDrop не требуется.

## Запуск через Docker

Нужен Docker Desktop / Docker Engine с Compose plugin. Также поддерживаются старый
`docker-compose` и Podman Compose. Python на хосте для этого способа не нужен.

Windows (Command Prompt или двойной щелчок):

```bat
docker-run.bat
```

Linux и macOS:

```bash
chmod +x docker-run.sh
./docker-run.sh
```

Скрипт создаёт `.env` из шаблона, если файл отсутствует, собирает образ и запускает
сервер. Каталог из `UPLOAD_DIR` и папка `logs` монтируются с хоста, поэтому загрузки и
журналы не исчезают при пересоздании контейнера. Внутри контейнера они доступны по
фиксированным путям `/data/uploads` и `/data/logs`; остальные настройки берутся из
`.env`. Порт снаружи и внутри контейнера задаётся общей переменной `PORT`.

Дополнительные команды одинаковы на обеих платформах:

```text
docker-run.sh --detach     # запустить в фоне (в Windows: docker-run.bat --detach)
docker-run.sh logs         # смотреть журнал контейнера
docker-run.sh status       # показать состояние и healthcheck
docker-run.sh restart      # пересобрать и перезапустить
docker-run.sh down         # остановить и удалить контейнер
```

На Windows скрипт попробует запустить Docker Desktop, если он установлен, но ещё не
готов. В Linux при недоступности Docker от текущего пользователя используется
беспарольный `sudo`, если он уже настроен; затем проверяется Podman. Эти fallback не
отключают firewall и другие механизмы безопасности.

> Для подключения с другого устройства разрешите Docker Desktop (или выбранный
> `PORT`) в firewall только для частной сети. Не публикуйте порт в интернете.

## Подключение с телефона или другого устройства

### Автоматическое предложение открыть WiFiDrop (Captive Portal)

WiFiDrop умеет отвечать на стандартные HTTP-проверки Captive Portal Android/ChromeOS,
iPhone/iPad/macOS и Windows. Если сервер или роутер **управляет DHCP/DNS этой Wi-Fi
сети**, ОС подключившегося устройства может показать системное уведомление вроде
«Войти в сеть» / «Открыть страницу сети» и открыть WiFiDrop без ручного ввода IP.

Для этого в `.env` включите:

```env
CAPTIVE_PORTAL_ENABLED=true
CAPTIVE_PORTAL_PORT=80
# Необязательно, но рекомендуется при постоянном IP сервера:
CAPTIVE_PORTAL_PUBLIC_URL=http://192.168.4.1:8000/
```

Кроме HTTP-сервера требуется сетевой уровень: DHCP должен выдать клиентам DNS, который
направляет системные connectivity-check домены на IP WiFiDrop, либо сеть должна
объявлять Captive Portal API через DHCP option 114 (RFC 8910). Готовый пример для
`dnsmasq` находится в `deploy/captive-portal/`. **На обычном домашнем роутере, которым
WiFiDrop не управляет, одно приложение на ПК не может принудительно вызвать такое
системное уведомление на чужом телефоне.**

Порт 80 может потребовать запуск с правами администратора/root. Поведение системного
уведомления также зависит от версии ОС, Private DNS, VPN и политики производителя.
Подробности: `deploy/captive-portal/README.md`.

### Обычное подключение

1. Убедитесь, что компьютер и второе устройство подключены к одному роутеру.
2. Запустите `run.bat` либо Docker-скрипт и не закрывайте окно сервера.
3. Найдите локальный IPv4-адрес компьютера одним из способов ниже.
4. Откройте на телефоне браузер и введите адрес, например
   `http://192.168.1.42:8000`.
5. Выберите или перетащите файлы и нажмите **Загрузить**.

## Установка как приложения (PWA)

WiFiDrop можно добавить в меню приложений или на главный экран. После этого он
открывается в отдельном окне с собственной иконкой, как обычное приложение. Сервер
на принимающем компьютере всё равно должен быть запущен через `run.bat`,
`docker-run.*` или `venv/bin/python start.py`.

- **Android / Chrome:** откройте WiFiDrop, нажмите **Установить** в шапке или выберите
  **Установить приложение** / **Добавить на главный экран** в меню браузера;
- **iPhone / iPad / Safari:** нажмите **Поделиться** → **На экран Домой**;
- **Windows, macOS, Linux:** откройте сайт в Chrome или Edge и нажмите
  **Установить** в шапке либо значок установки в адресной строке.

Service worker и автоматический системный диалог установки требуют безопасного
контекста: `localhost` считается безопасным, а для полного PWA-режима по локальному
IP нужен HTTPS с сертификатом, которому доверяет устройство. При обычном HTTP пункт
браузера **Добавить на главный экран** может создать простой ярлык — передача файлов
при этом продолжит работать.

### Как узнать IP-адрес компьютера

Самый удобный вариант из папки проекта:

```cmd
ipconfig
```

Скрипт также читает порт из `.env` и выводит готовые ссылки.

Стандартный способ Windows:

```bat
ipconfig
```

Найдите активный адаптер **Wireless LAN adapter Wi-Fi** и строку **IPv4 Address**.
Адрес обычно начинается с `192.168.` или `10.`. Не используйте `127.0.0.1` на
телефоне: этот адрес всегда указывает на само устройство.

## Где сохраняются файлы

По умолчанию рядом с проектом автоматически появляется структура:

```text
Files/
├── Documents/
│   └── 2026-07-27/
├── Images/
│   └── 2026-07-27/
├── Videos/
│   └── 2026-07-27/
├── Music/
│   └── 2026-07-27/
├── Archives/
│   └── 2026-07-27/
└── Other/
    └── 2026-07-27/
```

Основные правила классификации:

| Категория | Примеры |
| --- | --- |
| `Documents` | PDF, Word, Excel, PowerPoint, TXT, CSV, ODT |
| `Images` | JPG, PNG, GIF, WebP, HEIC, SVG, RAW |
| `Videos` | MP4, MKV, MOV, AVI, WebM |
| `Music` | MP3, FLAC, WAV, AAC, M4A, OGG |
| `Archives` | ZIP, RAR, 7z, TAR, GZ, ISO, IMG |
| `Other` | APK, исполняемые и неизвестные форматы |

Расширение имеет приоритет над MIME-типом браузера, поскольку браузеры часто
передают неизвестные типы как `application/octet-stream`. Если определить категорию
нельзя, используется `Other`.

## Конфигурация

Все рабочие настройки находятся в файле `.env` в корне проекта. После изменения
настроек перезапустите сервер.

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `APP_NAME` | `WiFiDrop` | Название в интерфейсе и логах |
| `HOST` | `0.0.0.0` | Сетевой интерфейс; для доступа из LAN оставьте `0.0.0.0` |
| `PORT` | `8000` | TCP-порт сервера, допустимо от 1 до 65535 |
| `UPLOAD_DIR` | `Files` | Папка сохранения, относительная или абсолютная |
| `MAX_FILE_SIZE_MB` | `2048` | Максимум на файл в МБ; `0` или `unlimited` — без ограничения |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `LOG_DIR` | `logs` | Папка журналов, относительная или абсолютная |
| `LOG_RETENTION_DAYS` | `30` | Срок хранения логов в днях |
| `UPLOAD_CHUNK_SIZE_KB` | `1024` | Размер блока потоковой записи, от 64 до 16384 КБ |
| `MAX_CONCURRENT_UPLOADS` | `1` | Число одновременно обрабатываемых загрузок, от 1 до 32 |
| `UPLOAD_BUSY_RETRY_AFTER_SECONDS` | `5` | Рекомендуемая пауза перед повторной отправкой, от 1 до 300 секунд |

По умолчанию сервер принимает одну загрузку одновременно. Если другое устройство уже
отправляет файл, новый запрос сразу получает сообщение «Сервер занят», а его тело не
записывается в папку загрузок. Остальная очередь на устройстве останавливается и
остаётся доступной для повторной отправки. Обычные страницы и проверка состояния
сервера продолжают работать. Для быстрого диска лимит можно увеличить, например:

```dotenv
MAX_CONCURRENT_UPLOADS=2
UPLOAD_BUSY_RETRY_AFTER_SECONDS=5
```
| `CAPTIVE_PORTAL_ENABLED` | `false` | Включить HTTP listener для системных проверок Captive Portal |
| `CAPTIVE_PORTAL_PORT` | `80` | Порт listener Captive Portal; системные проверки обычно используют HTTP/80 |
| `CAPTIVE_PORTAL_PUBLIC_URL` | пусто | Фиксированный URL WiFiDrop; без него LAN IPv4 определяется автоматически |

Пример переноса файлов на другой диск:

```dotenv
UPLOAD_DIR=D:\WiFiDropFiles
MAX_FILE_SIZE_MB=8192
PORT=8080
```

Чтобы полностью отключить ограничение размера одного файла:

```dotenv
MAX_FILE_SIZE_MB=unlimited
```

Значение `0` имеет тот же смысл. Ограничение свободного места на диске при этом,
разумеется, сохраняется. После изменения `.env` перезапустите сервер.

В `.env.example` хранится исходный шаблон настроек. Если `.env` был удалён, скопируйте
шаблон:

```bat
copy .env.example .env
```

Относительный `UPLOAD_DIR=Files` означает каталог `Files` в корне проекта. Например,
в текущем окружении он разрешается в `/root/projects/WiFiDrop/Files`. Можно сразу
указать абсолютный путь:

```dotenv
UPLOAD_DIR=/mnt/storage/WiFiDropFiles
```

## Архитектура проекта

Проект следует Clean Architecture: HTTP-слой знает о прикладных сервисах, сервисы
работают с доменными моделями, а правила классификации и сохранения не находятся в
роутах или интерфейсе.

```text

│   │   │   ├── health.py          # проверка доступности сервера
│   │   │   ├── pages.py           # HTML-страница
│   │   │   └── uploads.py         # endpoint загрузки
│   │   ├── dependencies.py        # сборка зависимостей сервисов
│   │   ├── error_handlers.py       # безопасные HTTP-ошибки
│   │   ├── router.py               # композиция роутов
│   │   └── schemas.py              # Pydantic-схемы API
│   ├── config/
│   │   └── settings.py             # валидация `.env`
│   ├── core/
│   │   ├── exceptions.py           # прикладные исключения
│   │   ├── logging.py              # логирование, ротация и очистка
│   │   └── security.py             # проверка имён и путей
│   ├── domain/
│   │   └── files.py                # категории и доменная модель файла
│   ├── services/
│   │   ├── file_classifier.py      # MIME/extension classifier
│   │   └── upload_manager.py       # потоковое безопасное сохранение
│   ├── static/
│   │   ├── css/                    # тема, компоненты и responsive-слои

│   ├── templates/

│   └── main.py                     # фабрика FastAPI и lifecycle
├── scripts/

├── tests/
├── .env
├── .env.example
├── pyproject.toml
├── requirements.txt
├── requirements-dev.txt

├── docker-run.sh                   # Docker-запуск на Linux/macOS
├── run.bat                         # установка при необходимости + запуск
├── setup.bat                       # отдельная установка

```

CSS намеренно разделён на:

- `theme.css` — цвета, размеры и design tokens;
- `base.css` — reset и базовая страница;
- `components.css` — визуальные компоненты;
- `animations.css` — анимации и `prefers-reduced-motion`;

JavaScript разделён по назначению: `queue-state`, `drop-zone`, `file-list`, `uploader`,
`notifications`, `theme`, `connection`, `utils` и точка сборки `app.js`.

## Безопасность и надёжность

- имена нормализуются в Unicode и проверяются на разделители пути и control-символы;
- запрещены traversal-пути и выход за корневую папку загрузок;
- учитываются недопустимые и зарезервированные имена Windows;
- максимальная длина имени ограничена с сохранением расширения;
- лимит размера проверяется по фактически прочитанным байтам;
- данные сначала пишутся в случайный `.part` в целевой папке;
- готовый файл появляется атомарно только после успешного завершения;
- при сбое временный файл удаляется;
- существующий файл никогда не перезаписывается;
- повреждённые multipart-запросы и ошибки валидации получают понятный ответ;
- traceback остаётся только в серверном журнале.

WiFiDrop рассчитан на доверенную локальную сеть и намеренно не содержит аккаунтов и
авторизации. Не настраивайте проброс порта роутера и не публикуйте сервер в интернете.
В гостевых или общедоступных сетях остановите приложение после передачи файлов.

## Логи

Основной журнал находится в `logs/wifidrop.log`. В нём фиксируются:

- запуск и корректная остановка сервера;
- дата и время каждого события;
- успешная загрузка, исходное и итоговое имя, категория и размер;
- IP-адрес клиента;
- отклонённые запросы, предупреждения и ошибки.

В полночь создаётся новый ротационный файл. Файлы старше `LOG_RETENTION_DAYS`
удаляются автоматически при запуске; `backupCount` дополнительно ограничивает число
ротаций.

## API

Frontend использует два локальных endpoint:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | проверка доступности сервера |
| `POST` | `/api/uploads` | загрузка одного multipart-поля `file` |

Множественная загрузка реализована несколькими независимыми запросами. Поэтому каждый
файл имеет собственный прогресс, ошибку и возможность повторной отправки без повторной
загрузки успешных файлов.

Если все слоты загрузки заняты, endpoint отвечает `503 Service Unavailable`, включает
заголовок `Retry-After` и возвращает безопасную JSON-ошибку:

```json
{
  "success": false,
  "error": "server_busy",
  "message": "Сервер занят другой загрузкой. Подождите немного и повторите отправку позже."
}
```

Пример успешного ответа:

```json
{
  "success": true,
  "message": "Файл успешно загружен.",
  "file": {
    "original_name": "photo.jpg",
    "saved_name": "photo (1).jpg",
    "category": "Images",
    "size": 153246,
    "relative_path": "Images/2026-07-27/photo (1).jpg"
  }
}
```

## Возможные проблемы

### Телефон не открывает сайт

- проверьте, что окно `run.bat` открыто и сервер не был остановлен;
- убедитесь, что оба устройства подключены к одной сети, а не к мобильному интернету;
- используйте IPv4 Wi-Fi адаптера, а не `localhost` и не `127.0.0.1`;
- разрешите Python в Windows Firewall для частных сетей;
- отключите VPN на время диагностики;
- гостевая Wi-Fi сеть может запрещать связь устройств друг с другом (AP/client
  isolation) — подключитесь к основной сети роутера;
- проверьте адрес с помощью `scripts\get_ip.ps1` ещё раз: DHCP может изменить IP.

### Порт уже занят

Проверить порт 8000:

```bat
netstat -ano | findstr :8000
```

Остановите конфликтующее приложение либо задайте, например, `PORT=8080` в `.env`,
перезапустите WiFiDrop и добавьте новый порт к адресу на телефоне.

### Python или `py` не найден

Переустановите Python 3.12+ с официального сайта и включите Python Launcher. Проверка:

```bat
py -3 --version
```

Для Docker-запуска Python на компьютере не требуется: установите Docker Desktop и
используйте `docker-run.bat`.

### Docker не запускается

- запустите Docker Desktop и дождитесь статуса **Engine running**;
- в Windows с WSL2 выполните `wsl --update`, затем перезапустите Docker Desktop;
- в Linux добавьте пользователя в группу `docker` либо настройте rootless Docker;
- если доступен Podman Compose, скрипт выберет его автоматически;
- проверьте конфликт порта и при необходимости измените `PORT` в `.env`.

### Не устанавливаются зависимости

- проверьте интернет при первом запуске;
- временно отключите блокировку PyPI корпоративным proxy/антивирусом;
- удалите только созданную папку `.venv` и повторно запустите `run.bat`;
- при необходимости выполните `setup.bat`, чтобы увидеть полное сообщение pip.

### Ошибка «файл превышает разрешённый размер»

Увеличьте `MAX_FILE_SIZE_MB` в `.env` и перезапустите сервер. Убедитесь, что на диске
достаточно свободного места для файла и его временной копии во время передачи.
Чтобы снять программный лимит полностью, задайте `MAX_FILE_SIZE_MB=unlimited` или `0`.

### Файл не сохраняется

- проверьте свободное место;
- убедитесь, что у текущего пользователя есть права записи в `UPLOAD_DIR`;
- не указывайте защищённые системные папки Windows;
- откройте последнюю запись в `logs\wifidrop.log`.

### Загрузка прерывается при блокировке телефона

Некоторые мобильные браузеры приостанавливают вкладки в фоне. Оставьте браузер
открытым и экран активным до появления статуса **Готово**. Не закрывайте окно сервера.

## Остановка и обновление

Для корректной остановки нажмите `Ctrl+C`. Все уже завершённые файлы останутся на
диске. Текущий `.part` удаляется обработчиком ошибки; после аварийного завершения
оставшиеся временные файлы автоматически очищаются при следующем запуске.

Чтобы принудительно переустановить обновлённые зависимости, запустите `setup.bat`.
Пользовательские файлы в `Files` и журналы в `logs` при этом не удаляются.

## Автономная Wi-Fi сеть с системным Captive Portal (Windows)

Если не хочется настраивать роутер, запустите `run_hotspot.bat`. Скрипт сам запросит права
администратора и включит специальный режим WiFiDrop: отдельный SSID, DHCP, локальный DNS,
DHCP Captive Portal option 114 и HTTP listener на порту 80. Телефон подключается к этой
сети и должен обнаружить портал штатным механизмом Android/iOS/Windows.

Параметры сети задаются в `.env` через `HOTSPOT_SSID`, `HOTSPOT_PASSWORD` и
`HOTSPOT_GATEWAY_IP`. Подробности и ограничения драйверов Windows находятся в
`deploy/captive-portal/README.md`.

## Windows Mobile Hotspot + графический интерфейс

Для современных Windows 10/11 рекомендуется запускать `run_gui.bat`.

1. Подключите USB Wi-Fi адаптер.
2. В Windows включите **Параметры → Сеть и Интернет → Мобильный хот-спот**.
3. Подключите телефон к созданной Windows сети.
4. Запустите `run_gui.bat`.
5. WiFiDrop автоматически найдёт виртуальный адаптер Mobile Hotspot и его внутренний IPv4-адрес, после чего покажет точный URL сайта.

GUI показывает состояние хот-спота, имя адаптера/IP, адрес сайта, состояние Captive Portal и полный вывод сервера.

### Важное ограничение Captive Portal в стандартном Windows Mobile Hotspot

Современный Windows Mobile Hotspot использует системный Internet Connection Sharing (ICS), который сам управляет DHCP и DNS приватной сети. Официальный WinRT API позволяет включать/выключать tethering и настраивать SSID/пароль, но не позволяет приложению добавлять DHCP option 114 или подменять системный DNS/DHCP. Поэтому WiFiDrop проверяет фактическую возможность занять DNS-порт и отображает реальный статус в GUI, а не обещает системное уведомление там, где Windows не предоставляет необходимого контроля.

Для гарантированного Android-уведомления «Войти в сеть» требуется сеть, где WiFiDrop контролирует DHCP/DNS (например, legacy Hosted Network при поддержке драйвера, Linux/OpenWrt-точка доступа или отдельный совместимый роутер/AP).
